# Handoff: HONA ORDER — система заявок на закуп

## Overview

HONA ORDER — внутренняя система заявок на закуп для распределённой организации (объекты: Регар, Душанбе, Худжанд, Бохтар, Куляб). Сотрудник создаёт заявку, руководитель согласует покупку, отдел закупа оценивает и закупает, руководитель согласует сумму, финансы оплачивают, склад выдаёт. Ключевая задача интерфейса — в любой момент показывать, **кто именно сейчас держит заявку и сколько дней она на этом этапе**.

В бандле два файла:

- `HONA ORDER — Приложение.dc.html` — кликабельный прототип, 15 экранов desktop + 4 макета mobile 390.
- `HONA ORDER — UI Kit.dc.html` — живой UI-kit: 18 разделов дизайн-системы (палитра, статусы, типографика, иконки, геометрия, компоненты, workflow, графики, тени, motion, запреты).

## About the Design Files

Файлы в бандле — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие внешний вид и поведение, а не продакшн-код для копирования. Задача — **воспроизвести эти макеты в существующей среде целевого кодовой базы** (React, Vue, Angular, Blazor, что используется) по её принятым паттернам и библиотекам. Если среды ещё нет — выбрать подходящий фреймворк и реализовать макеты в нём.

Технические детали прототипа (внутренний рантайм, инлайн-стили, CSS-переменные на `:root`, `support.js`) — артефакт среды прототипирования. В продакшне: токены — в тему/CSS-переменные или конфиг темы, экраны — в роутинг, переключение экранов через `display` — в обычную навигацию.

Файлы открываются в браузере напрямую: `HONA ORDER — Приложение.dc.html`.

## Fidelity

**High-fidelity.** Финальные цвета, типографика, отступы, размеры, состояния и микровзаимодействия. UI следует воспроизводить пиксельно точно, используя библиотеки и паттерны кодовой базы. Все значения ниже — точные.

Данные в макетах — примеры из ТЗ (РЗ-0048, Регар, 3 355,00). Логотип **нигде не нарисован**: везде стоит placeholder `logo slot` (44 px высотой, `1px dashed var(--line)`, radius 4 px, подпись 10/600 mono uppercase, `letter-spacing: .1em`, цвет `--grey`). Логотип брать только из официальных SVG/PNG assets организации, текстом не набирать.

### Пропорция цвета

70% white/mist · 20% ink/forest · 10% green. Зелёный не должен становиться фоном половины экрана.

### Зелёная шкала для графиков

`#0E3B21` · `#186B36` · `#22A74E` · `#7FBF95` · `#B7D6C2` · `#DCEAE1` — от большего значения к меньшему.

### Spacing

Только `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64` px. Grid gap 24 px, внешние поля 32 px desktop / 16 px mobile, content max-width 1240 px, sidebar 240 px, drawer 320 px.

### Radius

Только три значения:

- `0` — статусы, шапки таблиц, лейблы
- `2px` — поля ввода, фильтры, чипы, активный пункт nav, аватар
- `4px` — карточки, кнопки, модалки, панели, телефонные рамки

### Shadow

- `--shadow-1`: `0 1px 2px rgba(16,22,19,.06)` — Dark: `0 1px 2px rgba(0,0,0,.5)`
- `--shadow-2`: `0 8px 24px rgba(16,22,19,.14)` — Dark: `0 8px 24px rgba(0,0,0,.6)`

`shadow-2` только для modal, drawer, dropdown, sticky-панели действий. Больше теней в системе нет.

### Motion

Одна анимация: `150ms ease-out`. Без parallax, scroll-анимаций, переходов страниц, «прыгающих» элементов. Важно: transition ставится **только на hover-свойства**. На свойства, которые переключаются программно (активный пункт nav, тема), transition не ставить — иначе состояние догоняет клик с задержкой.

### Формат денег

- Верно: `3 355,00` — пробел разделяет тысячи, запятая — копейки, всегда два знака.
- В интерфейсе: `3 355,00 сомони`. В шапке таблицы: `Сумма, TJS`.
- До оценки закупом: `не оценена` (цвет `--grey`), **не `0,00`**. Ноль означает «закуп не требуется, всё со склада».
- Неверно: `3355`, `3,355.00`, `0,00` вместо «не оценена».

### Workflow заявки

Горизонтальная лента этапов, каждый — колонка `flex 1`, `min-width 130px`, `gap 8px`:

1. Полоса `height 4px`: completed — `--green`, current — статусный цвет этапа, future — `--line`, rejected — `#B8382C`

## Interactions & Behavior

- Клик по строке таблицы заявок → карточка заявки; активным в nav остаётся «Заявки»
- «Открыть очередь» на Дашборде → Согласование
- «Создать заявку» → макеты Mobile 390 (в продакшне — форма создания)
- «Согласовать» / «Отклонить» на любом экране → соответствующая модалка; закрытие по кнопке отмены, крестику и кнопке действия
- Переключение роли в топбаре → пересборка навигации, редирект на Дашборд, если текущий экран стал недоступен
- Переключение Light/Dark → `data-theme` на корне
- Гамбургер на mobile → drawer + scrim; закрытие по крестику и тапу по scrim
- Смена экрана сбрасывает скролл наверх
- Hover: строки таблицы `--zebra`, secondary-кнопки `--slate` рамка, пункты nav подсветка 8%, primary `--green-dark`
- Валидация: обязательные поля помечены `*`; причина отклонения обязательна — без неё кнопка не срабатывает, поле в error-состоянии
- Пустые состояния: `не оценена` вместо суммы, `—` вместо «Сейчас ждёт» для завершённых, «Не назначен» для руководителя объекта

## State Management

Прототип хранит состояние в CSS-переменных на `:root` (для мгновенной отрисовки) и в `localStorage`. В продакшне это обычный роутинг + стор:

| Состояние | Значения | Персистентность |
| --- | --- | --- |
| Активный экран | 15 экранов | `localStorage: hona-app-screen` |
| Роль | admin, employee, manager, procurement, finance, warehouse | `localStorage: hona-app-role` |
| Тема | light, dark | `localStorage: hona-ui-theme` |
| Открытая модалка | none, approve, reject | нет |
| Drawer каждого макета | open/closed, независимо | нет |
| Плотность таблиц | comfortable (44px), compact (36px) | нет |
| Толщина обводки иконок | 1.2–2.0, по умолчанию 1.6 | нет |

Данные заявки, нужные интерфейсу: номер, наименование, объект, автор, дата создания, статус, текущий этап, ответственный за этап, дней на этапе, позиции (наименование, количество, цена, сумма), итоговая сумма или флаг «не оценена», описание, журнал событий, причина отклонения.

Реальных запросов в прототипе нет. Действия, которых нет в API, добавлять не следует.

## Assets

- **Шрифты**: Manrope, JetBrains Mono, Noto Sans — Google Fonts. В продакшне лучше self-host.
- **Иконки**: Tabler Icons (outline), MIT. В прототипе inline SVG; в кодовой базе — пакет с переопределением stroke-параметров.
- **Логотип**: отсутствует. Везде `logo slot`. Нужны официальные SVG/PNG организации. Логотип не рисовать и не набирать текстом.
- **Изображений и фотографий в системе нет** — по требованию ТЗ фотографии товаров и объектов не используются.

## Не переносить в реализацию

- Фотографии кабеля и объектов, блок «Файлы», категории, комментарии к заявке
- Нижнее мобильное меню (таб-бар)
- Pie и donut диаграммы
- Произвольные KPI и действия, которых нет в API
- Хардкод цветов: только `var(--token)`, никогда `#fff` / `#111` напрямую
- Emoji, 3D-иконки, градиентные фоны, parallax, scroll-анимации
