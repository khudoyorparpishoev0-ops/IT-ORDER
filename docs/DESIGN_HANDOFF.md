# Handoff: IT-HONA CORE — платформа управления заявками на расходы

## Overview
Внутренний продукт **HONA CORE** для IT-HONA (Душанбе): менеджеры и руководители отделов согласуют, отслеживают и оплачивают заявки сотрудников на расходы. 8 разделов, светлая и тёмная темы, суммы в сомони (TJS).

Дизайн собран в двух шеллах, которые заказчик утвердил:
- **Вариант B «Диспетчер»** (значение `variant: "dispatch"`) — рабочий по умолчанию: тёмно-зелёный сайдбар 240 px, таблица заявок первым экраном, метрики компактной строкой, плотная сетка, очередь заявок списком в согласовании.
- **Вариант C «Светлый»** (`variant: "light"`) — тот же каркас, но сайдбар светлый (Paper + обводка 1 px Line), зелёный только в акцентах, средняя плотность.

Оба варианта обязательны к реализации: это одна кодовая база с переключателем шелла (тема + плотность + цвет сайдбара), а не два продукта. Вариант A «Воздух» (топ-навигация) в разработку не идёт — он остался в прототипе для истории.

## About the Design Files
Файлы в этом бандле — **дизайн-референсы, написанные в HTML**. Это прототип, показывающий вид и поведение, а не production-код для копирования. Задача — **воссоздать эти макеты в существующей среде вашего проекта** (React/Vue/Next, свои компоненты, свой роутинг, свои стили) по её принятым паттернам и библиотекам. Если среды ещё нет — выберите стек под задачу (в спецификации заказчика рекомендованы React 18+ / TypeScript / Tailwind, Recharts, xlsx, pdf-lib) и реализуйте макеты там.

Прототип использует собственный рантайм для стриминга разметки; не тащите его в продукт. Из него берите: структуру экранов, токены, размеры, копирайт, поведение.

`Табель расходов IT-HONA.dc.html` — один файл: разметка (шаблон) + класс логики + JSON-данные примеров. Иконочный спрайт встроен в начало файла (`<symbol id="ti-...">`).

## Fidelity
**High-fidelity.** Цвета, гарнитуры, кегли, отступы, радиусы, состояния и копирайт — финальные и выведены из брендбука IT-HONA rev. 1.0 (`spec/Брен бук ИТ-Хона.pdf`) и спецификации заказчика (`spec/Design_Specification_RU.md`). Верстку воссоздавайте пиксельно, но библиотечными компонентами вашего проекта.

Единственное исключение: **логотип** в шапке/сайдбаре — наборный стенд-ин (`IT-HONA` в Manrope 800, letter-spacing 0.06em + подпись `CORE` в моно). Брендбук запрещает набирать имя шрифтом рядом со знаком: подставьте официальные `ithona_logo_h-white.svg` / `ithona_logo_v-green.svg` из бренд-пакета (отдел маркетинга, brand@it-hona.tj).

### Форма, размеры, движение
- Радиусы: **0** — плашки, шапки таблиц, статус-плашки, теги; **2** — поля ввода, чипы, аватар-квадрат, пункты сайдбара; **4** — кнопки, карточки, модальные окна. «Таблетки» и круглые аватары запрещены.
- Обводки: 1 px `line` (разделители, карточки), 1 px `border-in` (поля, вторичные кнопки), 2 px `green` (акцент/активное), левая линия 2 px — цитаты и элементы истории.
- Фокус: `outline: 2px solid green; outline-offset: 2px`. Без смещения элемента.
- Тени (только экран): `sh1 = 0 1px 2px rgba(16,22,19,.06)`, `sh2 = 0 8px 24px rgba(16,22,19,.14)`. Третьего уровня нет, в печати теней нет.
- Углы-акценты только **60°** (30° как дополнение); 45° не используется. Срез угла — один на носитель: `clip-path: polygon(0 0, 100% 0, 100% calc(100% - 28px), calc(100% - 16px) 100%, 0 100%)` (баннер согласования, карточка «Срез угла» в дизайн-системе).
- Штриховка 60° для зон «в работе» и пустых состояний: `repeating-linear-gradient(60deg, mist 0 6px, transparent 6px 14px)`.
- Шаг отступов: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64. Контент до **1240 px**, боковые поля 32 px (desktop) / 16 px (mobile), межколонник 24 px.
- Анимация: **150 ms ease-out**. Никаких параллаксов и появления блоков по скроллу.
- Кнопки 44 px (мобильные 48 px), строка таблицы 44 px, ячейка padding по плотности.

## Interactions & Behavior
- **Навигация:** клик по пункту сайдбара меняет экран и закрывает открытый модал. Активный пункт — плашка, не подчёркивание.
- **Сортировка таблиц:** клик по «СОТРУДНИК · ОБЪЕКТ» сортирует по имени (`localeCompare` c локалью `ru`), по «СУММА» — по числу; повторный клик инвертирует направление. Иконка `arrows-sort` 14 px в шапке.
- **Фильтры:** чипы статусов и период; при пустом результате — пустое состояние со штриховкой и кнопкой сброса.
- **Строка таблицы:** hover `zebra`, курсор pointer, клик открывает модал заявки.
- **Решение:** переключение радио меняет цвет primary-кнопки, её подпись и placeholder комментария; отправка показывает тост. Комментарий при отклонении обязателен (валидация: непустая строка, иначе поле в состоянии ошибки — обводка 1 px `#B8382C` + подпись 13 `#B8382C`).
- **Тема:** переключатель в сайдбаре и в «Параметрах»; сохранять выбор в профиле пользователя.
- **Клавиатура:** все интерактивные элементы достижимы Tab, фокус — 2 px `green` с отступом 2 px; Esc закрывает модал; Enter/Space активируют кнопки.
- **Адаптив:** контент до 1240 px; блоки на flex/grid с `auto-fit`; согласование складывается в одну колонку ниже ~800 px; таблицы держат `min-width` 520–540 px и получают горизонтальный скролл только на очень узких экранах; для инженера в поле — карточки вместо таблицы, кнопки от 48 px, офлайн-режим (см. брендбук, стр. 41).
- **Запрещено:** анимации переходов между экранами, параллакс, появление блоков по скроллу, градиенты, тени под текстом, эмодзи.

## State Management
Локальное состояние экрана (в прототипе — поля класса):
- `variant`: `'dispatch' | 'light'` (в продукте — настройка шелла; `'air'` только в прототипе) → задаёт плотность, цвет сайдбара, порядок блоков на панели, наличие очереди в согласовании.
- `theme`: `'light' | 'dark'` — атрибут `data-theme` на корне.
- `screen`: активный раздел (в продукте — роут).
- `filter`: статус для раздела «Заявки»; `tab`: таб согласования.
- `sort`: `'name' | 'amount' | null`, `dir`: `1 | -1`.
- `decision`: `'approve' | 'reject'`; текст комментария.
- `modal`: открытая заявка или `null`.
- `toast`: `{ text, color }` с таймером 3200 мс (сбрасывать при размонтировании).
- `toggles`: три флага уведомлений.

Серверные данные: список заявок (id, ФИ, должность, объект, сумма, статус, дата), расходы заявки, история изменений, лимиты сотрудников, бюджет, реестр выплат, FAQ. Формат чисел — `ru-RU`: разделитель разрядов — пробел, копейки — запятая (`1 250 000,00`); валюта указывается в заголовке столбца или карточки (`СУММА, TJS`), в тексте — словом «сомони»; даты `00.00.2026`.

## Assets
- **Иконки:** контурный набор, встроенный в прототип SVG-спрайтом (`<symbol id="ti-*">`, 27 символов). Геометрия взята из Tabler Icons (MIT) и приведена к правилам брендбука: `stroke-width: 1.6` при 24 px, `stroke-linecap: butt`, `stroke-linejoin: miter`, `fill: none`, цвет через `currentColor`; размеры 14 / 18 / 20 / 24 px. Брендбук помечает набор услуг как **эскиз** — финальный комплект SVG рисуется в векторе и заменяет этот спрайт. Цветные иконки и эмодзи запрещены.
- **Шрифты:** Manrope и JetBrains Mono (Google Fonts, SIL OFL), Noto Sans для таджикского. В продукте — самохостинг `woff2` с `font-display: swap`.
- **Логотип:** в прототипе стенд-ин, заменить официальными SVG/EPS из бренд-пакета. Охранное поле — 1× толщины штриха знака; минимальный размер на экране: горизонтальная версия 96 px, вертикальная 72 px, знак без слова 24 px. JPEG логотипа не существует.
- **Фотографии:** в прототипе нет; при появлении — только реальные объекты, по правилам раздела 04 (без стоковых рукопожатий, без скруглений и рамок).
