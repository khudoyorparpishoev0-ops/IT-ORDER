# HONA CORE — платформа заявок на расходы

Внутренний продукт IT-HONA (Душанбе). Сотрудник подаёт заявку на расход,
руководитель согласует, финансы выплачивают. Суммы в сомони (TJS),
интерфейс русский, светлая и тёмная темы.

Дизайн зафиксирован хендоффом: `docs/DESIGN_HANDOFF.md`, брендбук
IT-HONA rev. 1.0 — `docs/Brand_Book_IT-HONA.pdf`. Брендбук приоритетнее всего
остального.

## Статус

| Фаза | Что | Готово |
|---|---|---|
| 1 | Каркас панели: токены, шелл, 8 разделов + дизайн-система, темы, варианты B/C | ✅ |
| 2 | Бэкенд: FastAPI, PostgreSQL, миграции, REST; панель работает на реальных данных | ✅ |
| 3 | Роли и вход: Admin / Manager / Finance / Viewer, JWT в httpOnly cookie | ⏳ |
| 4 | Цепочка согласования, уведомления о заявках старше 3 дней | ⏳ |
| 5 | Выгрузки: Excel-реестр и PDF | ⏳ |
| 6 | Развёртывание на сервере, HTTPS, бэкапы | ⏳ |

Данных-примеров в коде панели больше нет: всё приходит из API. Демонстрационный
набор загружается отдельной командой (см. «Первый запуск»).

## Как устроен обмен

```
браузер ──▶ nginx ──┬──▶ /            статика панели (React)
                    └──▶ /api, /health  FastAPI ──▶ PostgreSQL
```

Панель и API отдаются с одного origin, поэтому CORS не нужен.

## Жизненный цикл заявки

```
DRAFT ──отправить──▶ PENDING ──одобрить──▶ APPROVED ──оплатить──▶ PAID
                        │
                        └──отклонить──▶ REJECTED
```

Заявка на сумму не выше порога автоодобрения (`AUTO_APPROVE_THRESHOLD`,
по умолчанию 500,00 сомони) проходит из DRAFT сразу в APPROVED.
Обратных переходов нет: ошибочное решение исправляется новой заявкой,
история неизменяема. Править состав можно только у черновика.

## Разделы панели

Панель · Заявки · Согласование · Отчёты · Команда · Финансы · Параметры ·
Справка, плюс внутренняя страница-эталон «Дизайн-система» (`/system`).

Два варианта шелла из одной кодовой базы, переключаются в «Параметрах»:

- **B «Диспетчер»** — по умолчанию. Тёмно-зелёный сайдбар, таблица заявок
  первым экраном, плотная сетка.
- **C «Светлый»** — тот же каркас, светлый сайдбар, зелёный только в акцентах,
  средняя плотность.

## Первый запуск

```bash
cp .env.example .env      # заполнить POSTGRES_PASSWORD, при желании SECRET_KEY
mkdir -p data/postgres
docker compose up -d --build
```

Панель поднимется на порту из `WEB_PORT` (по умолчанию 8080). PostgreSQL и API
наружу не публикуются: снаружи доступен только nginx. Миграции применяются
автоматически при старте контейнера `api`, под advisory-локом.

Чтобы посмотреть панель на демонстрационных данных:

```bash
docker compose exec api python -m app.seed
```

Скрипт добавляет 4 объекта, 9 сотрудников и 10 заявок в разных статусах.
В рабочую базу его не запускать: данные условные, из макета. Повторный запуск
на непустой базе ничего не делает.

## Разработка

**Бэкенд**

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt

export POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=5432 POSTGRES_USER=hona
export POSTGRES_PASSWORD=... POSTGRES_DB=hona_core

alembic upgrade head
uvicorn app.main:app --reload      # http://localhost:8000/api/docs
```

**Фронтенд**

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173, /api проксируется на :8000
```

## Проверки перед коммитом

```bash
cd backend  && pytest              # нужна пустая база hona_core_test
cd frontend && npm run build       # tsc + vite
cd frontend && npm run preview &   # порт 4173
cd frontend && npm run smoke       # все разделы в обеих темах и обоих вариантах
```

`pytest` работает на настоящей PostgreSQL: SQLite не воспроизводит поведение
NUMERIC, timestamptz и ограничений, ради которых тесты и написаны. Заведите
базу `hona_core_test` — схему тесты создают сами.

`npm run smoke` открывает все разделы в Chromium, снимает скриншоты в `.shots/`
и падает при ошибке в консоли или ответе 4xx/5xx. Путь к браузеру задаётся
переменной `PW_CHROMIUM`, если браузер Playwright не установлен.

## Миграции

Схема меняется только миграциями Alembic, `create_all()` в рантайме запрещён.

```bash
cd backend
alembic revision --autogenerate -m "Что меняем" --rev-id 0002
alembic upgrade head
alembic check        # «No new upgrade operations detected» — схема совпадает
```

Ревизии нумеруются подряд: `0001`, `0002`, … Перед коммитом прогоните
`alembic downgrade base && alembic upgrade head` — миграция должна быть
обратимой.

## Развёртывание на сервере

Целевой сервер: Ubuntu 22.04, 2 ядра, 2 ГБ RAM, 30 ГБ SSD.

1. Обновить систему, создать пользователя без прав root, включить вход по
   SSH-ключу и выключить вход root по паролю.
2. Открыть в фаерволе только 22, 80 и 443:
   `ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable`
3. Поставить Docker и Docker Compose.
4. Склонировать репозиторий, заполнить `.env`, поднять стек.
5. Поставить HTTPS перед панелью (Caddy или nginx с certbot). Панель доступна
   из интернета, поэтому вход обязателен до открытия доступа сотрудникам.

Сборка фронтенда на 2 ГБ RAM проходит, но при нехватке памяти собирайте образ
на рабочей машине или в CI и переносите готовый.

## Правила, которые нельзя нарушать

- Токены только из `frontend/src/styles/tokens.css`. Новых цветов и радиусов в
  компонентах не заводить.
- Шрифты ставятся из npm и хостятся приложением. CDN запрещён.
- Статус всегда цвет **и** слово. Круглых аватаров, «таблеток» и тумблеров нет.
- Числа в формате ru-RU: `1 250 000,00`. Валюта — в заголовке столбца
  (`СУММА, TJS`) или словом «сомони».
- Секреты только в `.env`. В логи не писать пароли и токены.

## Предположения, которые нужно подтвердить

Эти решения приняты, чтобы не останавливать работу. Переделать их дёшево.

- **Порог автоодобрения — 500,00 сомони.** Взят из макета, меняется в `.env`
  переменной `AUTO_APPROVE_THRESHOLD` без правки кода.
- **Роли:** `employee` подаёт заявки, `manager` согласует, `finance` проводит
  оплату, `admin` может всё. Поле есть в базе, проверка прав появится в фазе 3
  вместе со входом. **До фазы 3 API открыт** — не выставляйте порт наружу без
  HTTPS и аутентификации.
- **Имя согласующего** передаётся клиентом (`actor`). После входа оно будет
  браться из сессии.
- **Одна заявка — одна выплата**, частичное возмещение не предусмотрено.
