# HONA CORE — платформа заявок на расходы

Внутренний продукт IT-HONA (Душанбе). Сотрудник подаёт заявку на расход,
руководитель согласует, финансы выплачивают. Суммы в сомони (TJS),
интерфейс русский, светлая и тёмная темы.

Дизайн зафиксирован хендоффом: `docs/DESIGN_HANDOFF.md`, брендбук
IT-HONA rev. 1.0 — `docs/Brand_Book_IT-HONA.pdf`. Брендбук приоритетнее всего
остального.

## Статус

| Фаза | Что | Готово |
|---|---|---|
| 1 | Каркас панели: токены, шелл, 8 разделов + дизайн-система, темы, варианты B/C | ✅ |
| 2 | Бэкенд: FastAPI, PostgreSQL, миграции, REST для заявок | ⏳ |
| 3 | Роли и вход: Admin / Manager / Viewer, JWT в httpOnly cookie | ⏳ |
| 4 | Согласование по цепочке, порог автоодобрения, уведомления | ⏳ |
| 5 | Выгрузки: Excel-реестр и PDF | ⏳ |
| 6 | Развёртывание на сервере, HTTPS, бэкапы | ⏳ |

Фаза 1 работает на данных-примерах из прототипа (`frontend/src/data/mock.ts`).
Этот модуль удаляется при подключении API.

## Разделы панели

Панель · Заявки · Согласование · Отчёты · Команда · Финансы · Параметры ·
Справка, плюс внутренняя страница-эталон «Дизайн-система» (`/system`).

Два варианта шелла из одной кодовой базы, переключаются в «Параметрах»:

- **B «Диспетчер»** — по умолчанию. Тёмно-зелёный сайдбар, таблица заявок
  первым экраном, плотная сетка.
- **C «Светлый»** — тот же каркас, светлый сайдбар, зелёный только в акцентах,
  средняя плотность.

## Разработка

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

Проверки перед коммитом:

```bash
npm run build        # tsc + vite, обязателен
npm run smoke        # прогон всех разделов в обеих темах, нужен npm run preview
```

`npm run smoke` открывает все разделы в Chromium, снимает скриншоты в `.shots/`
и падает при ошибке в консоли или ответе 4xx/5xx. Путь к браузеру задаётся
переменной `PW_CHROMIUM`, если браузер Playwright не установлен.

## Запуск в Docker

```bash
cp .env.example .env      # заполнить POSTGRES_PASSWORD и SECRET_KEY
mkdir -p data/postgres
docker compose up -d --build
```

Панель поднимется на порту из `WEB_PORT` (по умолчанию 8080). PostgreSQL
наружу не публикуется. Данные базы лежат в `data/postgres` на хосте —
именованные тома в проекте не используются, чтобы база не терялась при
пересоздании стека.

## Развёртывание на сервере

Целевой сервер: Ubuntu 22.04, 2 ядра, 2 ГБ RAM, 30 ГБ SSD.

1. Обновить систему, создать пользователя без прав root, включить вход по
   SSH-ключу и выключить вход root по паролю.
2. Открыть в фаерволе только 22, 80 и 443:
   `ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable`
3. Поставить Docker и Docker Compose.
4. Склонировать репозиторий, заполнить `.env`, поднять стек.
5. Поставить HTTPS перед панелью (Caddy или nginx с certbot). Панель доступна
   из интернета, поэтому вход обязателен до открытия доступа сотрудникам.

Сборка фронтенда на 2 ГБ RAM проходит, но при нехватке памяти собирайте образ
на рабочей машине или в CI и переносите готовый.

## Правила, которые нельзя нарушать

- Токены только из `frontend/src/styles/tokens.css`. Новых цветов и радиусов в
  компонентах не заводить.
- Шрифты ставятся из npm и хостятся приложением. CDN запрещён.
- Статус всегда цвет **и** слово. Круглых аватаров, «таблеток» и тумблеров нет.
- Числа в формате ru-RU: `1 250 000,00`. Валюта — в заголовке столбца
  (`СУММА, TJS`) или словом «сомони».
- Секреты только в `.env`. В логи не писать пароли и токены.
